# إدارة التراخيص — License management (seller guide)

## كيف يعمل الترخيص؟
- كل مفتاح هو حمولة JSON موقّعة بخوارزمية **ECDSA P-256 / SHA-256**: `ADDT1-<base64url(payload)>.<base64url(signature)>`.
- البرنامج يحمل **المفتاح العام** فقط (`src/shared/public-key.json`) ويتحقق من التوقيع محلياً بلا إنترنت.
- **المفتاح الخاص** (`tools/keys/private.jwk.json`) يبقى معك فقط؛ لا يُرفع إلى GitHub (مستثنى في `.gitignore`). احتفظ بنسخة احتياطية آمنة — بدونه لا يمكن إصدار مفاتيح جديدة، ولو أعدت توليده تتوقف كل المفاتيح القديمة عن العمل (تحتاج إصداراً جديداً من البرنامج).

## حمولة المفتاح
| الحقل | المعنى |
|---|---|
| `name` | اسم العميل / الجهة (يظهر في البرنامج) |
| `email` | اختياري |
| `type` | `subscription` للبيع (شهري / سنوي / تاريخ محدد). `lifetime` **داخلي لموظفي أصفان فقط** بلا انتهاء؛ لا يُباع، ويظهر في البرنامج بعبارة «ترخيص داخلي – موظفو أصفان» ولا تظهر كلمة «مدى الحياة» في أي مكان |
| `plan` | `monthly` أو `yearly` للاشتراكات (يظهر للعميل «اشتراك شهري/سنوي»)؛ يغيب عند تاريخ انتهاء مخصص |
| `expires` | تاريخ الانتهاء YYYY-MM-DD (للاشتراكات). قبل 30 يوماً يظهر للعميل تنبيه تجديد ببيانات التواصل، وبعده يتوقف البرنامج حتى إدخال مفتاح التجديد |
| `machine` | اختياري: معرّف الجهاز (XXXX-XXXX-XXXX-XXXX) يظهر للعميل في شاشة التفعيل والإعدادات |
| `modules` | اختياري: قائمة الوحدات المشمولة (`LEARN, DESIGN_LAB, FACTORY_TWIN, BUILDING_TWIN, FABRICATION_QC, ASSESSMENT`)؛ إن غابت = جميع الوحدات |
| `role` | `supervisor` لترخيص المشرف (مدرس/سوبر أدمن): يفتح لوحة المشرف ويسمح بحذف ملفات الطلاب |
| `seats` | اختياري: عدد المقاعد (للعرض والتنبيه فقط) |
| `notes` | اختياري |

## إصدار مفتاح
### سياسة البيع
- **العملاء**: اشتراك **شهري** أو **سنوي** (أو تاريخ انتهاء محدد). التجديد = إصدار مفتاح جديد بالتاريخ الجديد يُدخله العميل من الإعدادات ← الترخيص.
- **موظفو أصفان**: ترخيص داخلي بلا انتهاء (`--staff` أو خيار «ترخيص داخلي» في المولّد). خيار الموظفين **مخفي** في المولّد أثناء البيع؛ لإظهاره اضغط **Ctrl+Shift+S** أو افتح الصفحة برابط ينتهي بـ `#staff`. يظهر شريط تحذير برتقالي ما دام الوضع ظاهراً.

### الطريقة 1 — المولّد في المتصفح
افتح `tools/license-generator.html`، حمّل `private.jwk.json` (أو ألصقه واضغط «حفظ في هذا المتصفح»)، أدخل بيانات العميل، اختر **اشتراك شهري** أو **اشتراك سنوي** (يُحسب تاريخ الانتهاء تلقائياً من اليوم) أو تاريخاً محدداً، ثم الوحدات والدور، ثم «توليد» → انسخ المفتاح أو نزّل ملف `.lic` وأرسله للعميل.

### الطريقة 2 — سطر الأوامر
```bash
node tools/issue-license.mjs --name "جامعة العلوم التطبيقية – الهندسة الميكانيكية" --plan yearly --supervisor --seats 40
node tools/issue-license.mjs --name "Gulf Duct Factory LLC" --plan monthly --modules DESIGN_LAB,FACTORY_TWIN,ASSESSMENT
node tools/issue-license.mjs --name "Ahmad Ali" --expires 2027-06-30 --machine 1A2B-3C4D-5E6F-7A8B --email a@b.com
node tools/issue-license.mjs --name "ASFAN – أحمد (موظف)" --staff --supervisor      # داخلي فقط، بلا انتهاء
```
يطبع المفتاح ويكتب ملف `.lic`.

## التفعيل عند العميل
يلصق العميل المفتاح أو يحمّل ملف `.lic` في شاشة التفعيل. بعدها ينشئ ملفات الطلاب. ترخيص المشرف يُظهر زر «دخول المشرف» ويطلب إنشاء رمز PIN.

## سيناريوهات البيع
- **جامعة / مركز تدريب**: ترخيص واحد بدور `supervisor` يُثبَّت على أجهزة المختبر كلها (نفس المفتاح) + مجلد فصل مشترك على الشبكة؛ المدرس يدخل بالـ PIN من أي جهاز ليرى الجميع.
- **مصنع**: اشتراك سنوي (أو شهري للتجربة) مع الوحدات المطلوبة فقط.
- **فرد**: ترخيص مربوط بالجهاز (اطلب منه معرّف الجهاز من شاشة التفعيل).

## التحقق من مفتاح
في قسم «التحقق» بالمولّد، أو: `node -e "console.log(require('./src/main/license.js').validateKey(process.argv[1]))" ADDT1-...`

## تدوير المفتاح الخاص
`node tools/generate-keys.mjs --force` يولّد زوجاً جديداً ويحدّث المفتاح العام في البرنامج والمولّد؛ يلزم بعده إصدار نسخة جديدة من البرنامج وإعادة إصدار مفاتيح العملاء.
